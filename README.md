# 潮位报文归集台

港务水文组收到各潮位站的定长报文。归集员把一批报文贴进来，系统先按站码和时刻解析、去重，把能收的行放进**待落队列**；清洗由单独的「认领并清洗」动作做，入库再由「入库这一批」这个单独动作做。贴报文本身不直接落库。列数不对、站码坏了或时刻已经存在的行单独列出。

## 两步

| 动作 | 做什么 |
|------|--------|
| 解析进待落队列 | 校验四段、站码、十二位时刻、量程、质量旗，按站码+时刻去重。合格行记为「待清洗」，不写归集表 |
| 认领并清洗一行 | 定这一行的清洗方式与清洗后旗。先认领的结果保留，后到的记清洗争用 |
| 入库这一批 | 只把本批「已放行」的行写入归集表。还有「待清洗」行时整批拒绝 |

## 清洗定规

可疑旗在入库前只能按当日策略单定的一种方式处理：

| 策略单 | 可疑旗的处置 |
|--------|--------------|
| 严格清洗 | 必须改记实测（A）或改记插补（M）才能放行 |
| 留旗入库 | 允许可疑旗原旗入库，清洗详情与已入库详情都保留原旗 B |

实测旗、插补旗一律原旗放行。清洗方式写进当日策略单后，本日不得更换；清洗方式或清洗设置的其它细节与策略单偏离时，该次清洗记**清洗方式不符**，行保持待清洗。

待落队列里还有行时不许改清洗设置。

## 页面

待落页分四块：待落列表（待清洗 / 已放行 + 方式名）、清洗详情（清洗前后的旗对照）、清洗设置（当日策略单）、待落队列（认领清洗的入口）。已入库单独一页，只列已经落库的行，并对照清洗前旗与入库旗。
